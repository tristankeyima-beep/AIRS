# 代码节点出入参说明：获取备案病种

对应代码：`代码节点.py`

## 节点作用

从上游完整认定标准 `certification_list` 的 `meta` 中，提取备案病种名称和编码，作为下一步 ADP 知识库检索的条件。

```text
certification_list
  → 本代码节点：chronicDiseaseName、chronicDiseaseCode
  → ADP 知识库检索
  → 检索结果重组为 rule_repository
```

本节点不检索知识库，也不读取或修改 `ruleRepository`。

## 腾讯平台配置

### 输入变量

| 变量名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `certification_list` | `obj` | 是 | 完整认定标准对象。建议在腾讯平台配置为 `obj`。 |

兼容历史 JSON 字符串入参，以及只含一个对象的数组入参。

### 输出变量

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `chronicDiseaseName` | `str` | 备案病种名称，用于知识库检索。 |
| `chronicDiseaseCode` | `str` | 备案病种编码，用于知识库检索。 |

## 入参结构

```text
certification_list: Object
  meta: Object
    chronicDiseaseName: String
    chronicDiseaseCode: String
```

`ruleRepository`、`logicTopology` 等其他字段可以保留在入参中，但本节点不会使用它们。

## 测试入参

```json
{
  "certification_list": {
    "meta": {
      "version": "V2026042804",
      "chronicDiseaseName": "糖尿病",
      "chronicDiseaseCode": "M01603"
    },
    "ruleRepository": []
  }
}
```

## 对应出参

```json
{
  "chronicDiseaseName": "糖尿病",
  "chronicDiseaseCode": "M01603"
}
```

## 异常情况

以下输入会直接报错，避免以空病种条件检索知识库：

- `certification_list` 为空、空数组或不是对象。
- JSON 字符串无法解析。
- 缺少 `meta` 对象。
- `meta.chronicDiseaseName` 或 `meta.chronicDiseaseCode` 为空。
