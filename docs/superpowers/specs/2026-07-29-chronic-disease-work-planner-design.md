# 门诊慢特病工作规划与任务编排 Skill 设计

## 1. 目标

新增独立 Skill `chronic-disease-work-planner`，中文名称为“门诊慢特病工作规划与任务编排助手”。

该 Skill 面向不熟悉 Agent 和 Skill 的医保业务用户。它负责理解用户目标、识别已有资料、补齐关键输入、拆解复杂任务、选择合适能力、生成 Markdown 工作计划，并根据用户选择只制定计划或自动连续执行。

它编排以下六项能力：

1. `chronic-disease-knowledge-retrieval`：门诊慢特病知识库检索；
2. `chronic-disease-certification-standard-flash`：认定标准生成；
3. `chronic-disease-material-catalog-flash`：材料证据编目与归位；
4. `chronic-disease-material-precheck-flash`：申请材料预检与补件清单；
5. `chronic-disease-standard-version-impact-flash`：认定标准版本比对与影响分析；
6. `chronic-disease-certification-qc-flash`：审核质控。

## 2. 核心定位

该 Skill 是引导式规划助手，不是新的审核算法，也不替代六个被编排的 Skill。

它负责：

- 用业务语言理解用户想解决的问题；
- 判断请求是单一任务还是复杂任务；
- 识别患者材料、认定标准、审核结果和政策或临床依据；
- 在缺少认定标准时主动调用知识库检索；
- 向用户说明可选择的任务方向和对应成果；
- 每轮集中询问一至三个会改变工作路线的问题；
- 生成和更新 Markdown 工作计划；
- 在自动连续执行模式下将上一步成果传给下一步；
- 保留各下游 Skill 自身的业务确认关口；
- 汇总实际交付物、未完成项和后续建议。

它不负责：

- 自行编造认定标准、政策、医学事实或患者材料；
- 将临床指南自动升级为医保准入条件；
- 替用户确认标准版本、规则歧义或材料完整性；
- 为了显得完整而机械调用全部 Skill；
- 给出最终医保资格认定；
- 生成独立 JSON 或 HTML 工作计划文件。

## 4. 四类关键业务输入

规划助手先识别四类输入对象：

| 输入对象 | 典型内容 | 关键判断 |
|---|---|---|
| 患者申请材料 | 病历、检查、检验、诊断、处方、住院记录 | 是否可读、是否需要编目、是否已确认完整 |
| 病种认定标准 | 一份或多份自然语言或结构化标准 | 来源、地区、版本、是否已确认采用 |
| 某次审核结果 | 审核结论、逐规则结果、证据引用、推理过程 | 是只有结论，还是包含详细审核过程 |
| 政策与临床依据 | 政策文件、指南、专家共识、诊疗规范 | 是正式医保标准，还是业务或临床参考 |

文件数量不能直接决定任务类型：

- 多份患者材料不触发标准版本比对；
- 一份政策正文和附件可能属于同一套标准；
- 两份不同时间、地区或来源的认定标准可以触发版本比对；
- 用户明确提出新旧比较、标准修订或影响分析时触发版本比对。

## 5. 触发规则

以下情况自动触发规划助手：

- 用户明确要求制定工作计划、拆解任务或安排步骤；
- 用户目标模糊，例如“帮我把这个病种审核工作处理一下”；
- 请求涉及知识查询、标准生成、材料整理、材料预检、版本比对或审核质控中的两个或以上环节；
- 用户提供大量内容，但没有说明希望得到什么成果；
- 当前信息不足以判断应使用哪个 Skill；
- 用户希望修改认定标准，且任务可能涉及依据检索、标准生成和版本影响分析。

以下情况不应强制触发：

- 用户目标单一且明确；
- 用户明确要求调用某个具体 Skill；
- 用户只要求改写、排版或查看已经生成的成果；
- 当前请求不属于门诊慢特病业务范围。

单一明确任务直接交给对应 Skill，避免过度规划。

## 6. 面向非专业用户的交互原则

规划助手采用热情、友好、温暖且清晰的表达方式。

当意图不明确时：

1. 先说明已经识别到用户提供了什么；
2. 用业务语言说明当前可以完成哪些事情；
3. 每个选项说明会产生什么成果；
4. 每次提供两至三个主要选项；
5. 可以给出推荐项和推荐理由，但不替用户决定；
6. 能立即提供低风险、有帮助的简要回答时，先回答，再引导是否进入完整任务；
7. 不要求用户理解或说出 Skill 名称。

示例：

```text
我已经看到您提供了患者材料、认定标准和一份原审核结果。

我可以帮您：
1. 复核原审核质量，生成质控报告；
2. 不看原审核，单独检查材料与标准的对应情况，生成补件清单；
3. 先把材料整理成目录、时间线和待核对事项。

如果您主要想确认原审核是否可靠，我建议选择第 1 项；如果准备重新申报或补材料，我建议选择第 2 项。您希望先做哪一种？
```

## 7. 关键问题询问规则

每轮集中询问一至三个问题，不强制一次只问一个，也不一次抛出长问卷。

优先询问：

1. 最终希望得到什么成果；
2. 当前已经具备哪些材料、标准或审核结果；
3. 希望只制定计划，还是自动连续执行。

补充规则：

- 能从上下文和已上传材料中判断的信息不重复询问；
- 只有会改变任务顺序、能力选择或成果范围的问题才询问；
- 用户不确定时给出推荐默认项及原因；
- 一轮回答后仍存在关键缺口时，可以继续下一轮；
- 详细澄清问题必须在工作计划之外单独询问。

## 8. 两种执行模式

### 8.1 只制定计划

规划助手完成：

- 意图识别；
- 输入盘点；
- 缺失项说明；
- 任务拆解；
- Skill 选择；
- 前后依赖；
- 预期成果；
- Markdown 工作计划。

生成计划后停止，不调用下游 Skill。

此模式中的后续步骤保持“⬜ 计划执行”，不因本轮没有实际执行而标记为“❌ 未完成”。“❌”只用于用户要求执行但最终没有完成的步骤。

### 8.2 自动连续执行

自动连续执行的含义是：

> 用户确认工作计划后，规划助手按照计划自动推进。当前步骤所需信息已经具备时，不再反复询问是否继续；遇到业务确认、材料补充或执行阻断时暂停，得到用户回复后从原位置继续。

授权流程：

1. 用户选择“自动连续执行”；
2. 规划助手展示完整工作计划；
3. 用户确认“按此计划开始执行”；
4. 规划助手按计划调用相应 Skill；
5. 没有确认关口时自动进入下一步；
6. 遇到确认关口时更新计划状态，并在计划外单独提问；
7. 用户回答后更新计划并继续；
8. 完成后汇总交付物和未完成项。

自动连续执行不等于：

- 自动调用全部 Skill；
- 自动替用户确认；
- 自动选择存在争议的标准；
- 自动补造缺失事实；
- 自动改变用户任务目标。

## 9. 暂停与重新规划

以下情况必须暂停：

- 检索到多份候选标准，需要确认采用范围；
- 标准存在会改变认定范围的歧义；
- 认定标准草案等待用户确认；
- 材料清单等待用户确认完整；
- 多份标准的比较顺序无法确认；
- 当前输入不足以继续；
- 下游 Skill 执行失败或没有形成正式成果；
- 执行结果导致后续路线发生重大变化。

需要重新规划时：

- 说明触发变化的事实；
- 保留已完成步骤及交付物；
- 只调整受影响的后续步骤；
- 展示更新后的 Markdown 计划；
- 重大变化再次取得用户确认。

## 10. 六项能力路由

| 用户目标或当前缺口 | 使用能力 | 核心成果 |
|---|---|---|
| 查询认定标准、政策、指南、共识或依据 | 知识库检索 | 知识结果、来源和原文片段 |
| 将自然语言条件加工为结构化标准 | 认定标准生成 | JSON 和离线认定标准页面 |
| 整理杂乱患者材料 | 材料证据编目与归位 | 材料目录、时间线、事实和关联线索 |
| 检查现有材料并形成补件建议 | 申请材料预检与补件清单 | JSON 和离线预检页面 |
| 比较两份以上标准或分析标准修订影响 | 认定标准版本比对与影响分析 | JSON 和离线影响分析页面 |
| 复核某次原审核结果 | 审核质控 | JSON 和离线质控页面 |

上一步成果可以作为下一步输入，但下一项 Skill 的确认关口不能被绕过。

## 11. 缺少认定标准时的公共前置流程

材料预检、版本比对和审核质控等任务经常依赖认定标准。用户没有提供时，规划助手自动调用知识库检索。

流程：

```text
识别病种、地区、时间和任务
→ 调用知识库检索
→ 展示候选标准名称、来源、版本和条件摘要
→ 在计划外询问用户如何处理
→ 用户选择直接采用、结构化生成、补充修正、继续检索或版本比对
→ 更新计划并继续
```

检索后的选择：

- 直接采用：标记为用户已确认采用的自然语言标准；
- 生成结构化标准：调用认定标准生成 Skill；
- 补充或修正：结合用户补充内容重新检索或生成；
- 继续检索：补充地区、时间、来源或具体条件；
- 多版本比对：调用版本比对 Skill。

没有检索到合适标准时，说明知识库当前未定位到可采用内容，请用户补充政策文件、标准原文或更明确条件，不得编造。

## 12. 是否建议结构化标准

| 后续任务 | 默认建议 |
|---|---|
| 只查询政策、指南或认定条件 | 直接使用检索结果 |
| 材料证据编目与归位 | 不需要认定标准 |
| 简单材料预检，标准条件清晰 | 可以直接使用已确认自然语言标准 |
| 复杂材料预检，存在多层逻辑 | 建议先生成结构化标准 |
| 逐规则审核质控 | 建议先生成结构化标准 |
| 简单审核结论复核 | 可以使用已确认自然语言标准 |
| 多版本标准比较 | 直接进入版本比对 |
| 后续需要复用、维护或导入审核系统 | 建议生成结构化标准 |

规划助手说明推荐理由，由用户决定是否结构化。

## 13. 标准有效性、合理性和可执行性

用户询问“这个认定标准对不对、合不合理”时，可能包含三类意图：

1. 是否为现行有效的政策标准；
2. 在临床或医保业务上是否合理；
3. 是否清晰、完整并可被智能审核执行。

路由：

- “是不是最新、现在是否有效、政策出处” → 知识库检索；
- “临床有没有依据、条件是否合理” → 检索政策、指南和专家共识，再由调用模型讨论；
- “能否配置、规则怎么拆、逻辑是否清楚” → 认定标准生成；
- 只说“对不对”且上下文不足 → 在计划外说明三种理解，请用户选择。

临床指南、专家共识和诊疗规范只能作为业务讨论或修订参考，不自动成为现行医保准入条件。

## 14. 标准修改与版本影响路线

用户提出修改认定标准时：

```text
引导用户提供现行标准
→ 询问修改内容和原因
→ 检索政策、指南、共识或其他依据
→ 生成拟修订标准
→ 用户确认拟修订版本
→ 比较现行版本和拟修订版本
→ 输出新增、删除、修改、逻辑变化和受影响审核规则
→ 可选引导提供真实患者材料
→ 按两个版本分别进行规则证据判读
→ 比较同一患者在两个版本下的结果变化
```

真实患者材料为可选项。没有患者材料时仍可完成标准差异和审核规则影响分析。

## 15. 典型意图处理

### 15.1 “帮我审核这些材料”，但没有原审核结果

- 不进入审核质控；
- 引导为申请材料预检；
- 输出条件证据、信息不足项和补件清单；
- 不给正式通过或不通过结论；
- 用户后续补充原审核结果时，可询问是否增加审核质控任务。

### 15.2 只有标准，询问需要准备什么材料

- 先由调用模型根据已确认标准给出通用准备清单，该回答不是正式材料预检成果；
- 回答后询问用户是否已有部分申请材料；
- 用户同意后进入材料预检。

### 15.3 同时提供患者材料、标准和审核结果，只说“帮我看看”

在计划外引导用户选择：

- 审核质控：复核原审核质量；
- 材料预检：单独检查材料与标准；
- 材料编目：只做客观整理。

说明每种任务对应的成果物，不默认替用户选择。

### 15.4 两份标准和一份患者材料，询问哪个更容易通过

- 调用版本比对 Skill；
- 分别形成两套规则证据判读；
- 中立说明条件差异、证据差异、结果差异和原因；
- 不推荐采用更宽松的标准。

### 15.5 上传多份文件但没有明确目标

- 先识别文件属于患者材料、标准、审核结果还是政策与临床依据；
- 说明可以完成的两至三个任务方向；
- 说明每个方向的交付成果；
- 等用户选择后再制定计划或执行。

## 16. 省局内网授权前提

系统运行在省局内网环境，`knowledge_qa` 为已授权内部应用。

用户确认“自动连续执行”和完整工作计划后：

- 视为授权调用 `chronic-disease-knowledge-retrieval`；
- 可以根据任务需要将患者原始材料传给知识检索 Skill；
- 无需就患者材料在内部 Skill 之间传递重复询问；
- 知识检索结果的最终业务解读仍由调用模型完成。

认定标准选择、规则解释、材料完整性和版本顺序等业务确认仍须保留。

## 17. Markdown 工作计划

工作计划只展示：

- 任务目标；
- 执行方式；
- 已具备内容；
- 需要提前准备的内容；
- 步骤、依赖和状态；
- 当前等待确认的问题摘要；
- 实际交付物超链接；
- 未完成原因；
- 最终执行汇总。

工作计划不包含：

- 完整澄清问题；
- 长选项；
- 要求用户直接在计划中回复的交互文本；
- 对话历史；
- 伪造的交付物链接。

### 17.1 状态标识

| 标识 | 含义 |
|---|---|
| ✅ | 已完成 |
| ❌ | 未完成或执行失败 |
| ⏳ | 正在执行 |
| ⏸️ | 等待用户确认或补充材料 |
| ⬜ | 尚未开始 |

自动连续执行结束时，所有实际执行步骤必须收敛为：

- ✅ 已完成；
- ❌ 未完成，并说明原因。

只制定计划模式中的未来步骤保留“⬜ 计划执行”，不使用“❌”制造已经执行失败的误解。

### 17.2 计划示例

```markdown
# 门诊慢特病工作计划

> 执行方式：自动连续执行
>
> 当前进度：2 / 5
>
> 当前状态：等待确认采用的认定标准

## 一、任务进度

| 步骤 | 工作任务 | 使用能力 | 状态 | 交付物 |
|---|---|---|---|---|
| 1 | 检索脑梗死认定标准 | 门诊慢特病知识检索 | ✅ 已完成 | 检索结果已在对话中返回 |
| 2 | 确认本次采用的认定标准 | 规划助手 | ⏸️ 正在确认 | 暂无 |
| 3 | 生成结构化认定标准 | 认定标准生成 | ⬜ 尚未开始 | 执行后生成 |
| 4 | 整理患者申请材料 | 材料证据编目与归位 | ✅ 已完成 | [查看材料编目报告](实际链接) |
| 5 | 生成材料预检与补件清单 | 申请材料预检 | ⬜ 尚未开始 | 执行后生成 |

## 二、当前状态

> ⏸️ 正在确认：本次采用哪一份认定标准。

确认完成后，将继续生成结构化认定标准，并开展申请材料预检。

## 三、交付物汇总

| 交付物 | 状态 | 查看或下载 |
|---|---|---|
| 知识检索结果 | ✅ 已返回 | 对话结果；有来源地址时提供原文链接 |
| 材料编目页面 | ✅ 已生成 | [打开离线页面](实际链接) |
| 结构化认定标准 | ❌ 尚未生成 | 等待确认采用标准 |
| 材料预检与补件清单 | ❌ 尚未生成 | 依赖结构化认定标准 |
```

## 18. 澄清问题与工作计划分离

工作计划只记录：

- 卡在哪个问题；
- 状态为“正在确认”；
- 哪些后续步骤暂停；
- 确认后继续什么任务。

规划助手在工作计划之外单独说明背景、提出问题并提供选项。

用户回答后：

- 更新原计划状态；
- 将确认步骤标记为完成；
- 将下一步骤标记为执行中；
- 自动连续执行模式下立即继续。

`SKILL.md` 必须明确禁止把完整澄清对话、长选项或要求用户回复的内容写入工作计划。

## 19. 交付物超链接规则

1. 下游 Skill 已生成文件时，交付物名称必须是可点击链接；
2. 知识库返回政策原文链接时，保留实际来源链接；
3. 一个步骤有多个成果时分别列出；
4. 尚未生成的成果显示“❌ 尚未生成”，不得伪造链接；
5. 链接只能采用下游 Skill 或平台实际返回的地址；
6. 自动执行完成后，在回答开头提供“本次交付”快捷入口；
7. 链接失效或平台没有返回链接时，明确标注无法访问，不将其写成已交付。

示例：

```markdown
## 本次交付

- [认定标准数据文件](实际链接)
- [认定标准离线页面](实际链接)
- [材料预检与补件清单](实际链接)
```

## 20. 文件职责

### `SKILL.md`

负责触发边界、总体流程、两种执行模式、确认关口、下游 Skill 调用和禁止事项。

### `references/intent-routing.md`

负责四类输入识别、六项能力映射、典型意图、缺少标准的回退路线和标准修改路线。

### `references/continuous-execution.md`

负责自动执行授权、状态更新、暂停、恢复、重新规划和下游成果传递。

### `references/markdown-plan-template.md`

负责 Markdown 工作计划结构、状态图标、交付物链接、完成与未完成收口，以及“计划与澄清问题分离”。

### `使用说明.md`

面向业务用户解释适用场景、两种执行模式、使用流程、成果形式和示例问题。

## 21. 测试策略

### 21.1 触发与不过度触发

- 明确单一任务直接路由，不生成冗长计划；
- 明确要求计划或涉及两个以上能力时触发；
- 大量文件但目标不清时先引导；
- 与慢特病无关的普通问题不触发。

### 21.2 执行模式

- 只制定计划模式不调用下游 Skill；
- 自动连续执行必须先取得完整计划确认；
- 无确认关口时连续进入下一步；
- 有确认关口时暂停并单独提问；
- 用户回答后从暂停点恢复；
- 重大变化触发重新规划。

### 21.3 缺少标准

- 无标准的材料预检任务先检索知识库；
- 检索到一份候选标准后要求确认采用方式；
- 检索到多份标准时支持选择、继续检索或版本比对；
- 无结果时不编造标准；
- 用户选择结构化时调用认定标准生成。

### 21.4 意图分类

- 无原审核结果的“审核材料”进入材料预检；
- “标准是否有效”进入知识检索；
- “标准是否合理”检索政策和临床依据后讨论；
- “标准能否配置”进入认定标准生成；
- “修改标准”形成现行版、拟修订版和版本比对路线；
- 两份标准加患者材料形成中立的双版本判读；
- 同时提供材料、标准和审核结果但意图模糊时提供三个业务选项。

### 21.5 Markdown 可视化

- 已完成步骤显示 ✅；
- 最终未完成步骤显示 ❌ 和原因；
- 执行中、等待确认和尚未开始状态正确；
- 计划中不出现完整澄清选项；
- 已生成交付物使用实际超链接；
- 未生成成果没有伪造链接；
- 最终回答开头提供交付物快捷入口。

### 21.6 业务边界

- 临床指南不自动升级为医保准入条件；
- 多份患者材料不误触发标准版本比对；
- 标准正文与附件不自动当成不同版本；
- 规划助手不输出最终医保资格结论；
- 下游 Skill 的确认关口不被绕过。

## 22. 验收标准

- 非专业用户无需知道 Skill 名称即可完成选择；
- 复杂任务能稳定拆解为最短可执行路线；
- 用户没有认定标准时仍可通过知识库启动任务；
- 计划清楚展示进度、依赖、暂停点和交付物；
- 澄清问题与计划正文严格分离；
- 两种执行模式行为明确且可验证；
- 自动执行可以正确暂停、恢复和重新规划；
- 标准修改能形成现行与拟修订版本比对，并可选加入真实患者材料；
- 所有实际交付物都有可点击链接；
- 未完成事项以 ❌ 收口并说明原因；
- Skill 目录、说明文档和测试均符合仓库现有约定。
