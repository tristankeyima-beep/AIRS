# 认定标准版本比对与影响分析 Flash Skill 设计

## 1. 目标与边界

新增独立 Skill `chronic-disease-standard-version-impact-flash`。它对用户提供的两份或以上认定标准做可追溯的条件、逻辑和取证要求比对；用户额外提供申请材料时，分别按每份标准完成规则证据判读并解释差异来源。正式成果为 JSON 与离线 HTML。

它不评价原审核结果，不使用审核质控的风险语义，也不把材料判读称为最终经办资格结论。

## 2. 标准确认与排序门禁

每份标准分别盘点来源、病种、文件标注版本、生效时间、废止/替代信息和完整原文。每份自然语言标准均按审核标准生成 Skill 的规则、提取项、逻辑树方式解析；影响含义的歧义必须统一澄清。

比较顺序只能来自原文明确的版本/生效信息或用户指定。若无法确认新旧顺序，成果只称“多版本差异”，不得称某份为新标准或旧标准。用户确认标准解释、纳入范围和比较顺序后，才生成正式成果。

现有审核标准生成 Skill 中 `VYYYYMMDD` 可以表示成果生成日期，不得单独当作政策生效日期使用。

## 3. 版本差异与影响分析

每份标准均保留独立规则命名空间，例如 `S1:R001`、`S2:R001`，不同版本同名规则不得自动视为同一规则。先基于原文和结构化规则建立跨版本的可比条件组，再产生以下分类：

- 条件新增。
- 条件删除。
- 条件修改：阈值、单位、时长、次数、范围、适用对象、排除项或证据要求变化。
- 逻辑变化：AND/OR 或共享前提变化。
- 仅表述变化：存在文字变化，但无法依据原文确认业务含义变化。

每一项差异都保留各版本规则和原文定位。`仅表述变化` 和无法安全匹配的规则标为待人工确认，不强行映射。

## 4. 可选申请材料判读

用户未提供申请材料时，只完成标准差异和规则影响分析。提供材料时，先展示材料清单并取得明确完整性确认，再对每份标准独立生成 `versionAssessments`：材料事实、逐规则证据状态和版本下的参考判读。

逐规则状态仅使用 `met`、`not_met`、`unknown`，整体仅使用 `meets`、`does_not_meet`、`uncertain`，页面翻译为中文并标注“规则证据判读，仅供审核参考”。它不读取原审核结果，也不使用 `two_stage_non_blind`、错误通过或错误拒绝等字段。

`assessmentDelta` 只在材料判读改变时记录：涉及版本、变化规则、差异类型和原文依据；未提供材料时为空数组。

## 5. 数据模型与 HTML

根对象采用 `flash-1.0` 与 `standard_version_impact` 模式，包含：

`schemaVersion`、`mode`、`meta`、`standardInputs`、`analysisRecord`、`conditionGroups`、`changes`、`materialDocuments`、`versionAssessments`、`assessmentDelta`、`confirmation`。

页面展示版本与排序依据、可比条件组、差异清单、受影响规则、可选的各版本规则证据判读与变化原因、原始标准/材料和确认记录。每个版本的材料判读和差异解释都来自 JSON；页面不出现审核质控报告中的五维检查、原审核结论或风险。

## 6. 复用与验收

直接复用审核标准生成 Skill 的标准解析、连续原文引用、逻辑树、歧义确认与结构化标准输入适配；可选材料判读参考审核质控 Flash 的材料事实和逐规则状态；复用材料编目 Flash 的材料完整性确认和离线 HTML 数据槽校验。

不复用审核质控 Flash 的原审核输入、两阶段非盲复核、质控维度、问题与风险模型；不将审核标准生成 Skill 的成果日期错误当作政策版本日期。

验收覆盖：两版本与三版本比对、顺序由原文/用户指定/无法确认三类情形、同名规则跨版本隔离、条件新增删除修改、逻辑变化、仅表述变化、无材料与有材料分支、材料未确认阻断、跨版本判读变化、JSON/HTML 等值与敏感信息拦截。
