# 门诊慢特病审核质控 Skill 优化设计

## 目标

在不放宽模式 1 正式标准契约的前提下，让模式 2 正确接收外部审核系统的结构化标准，减少模型构造报告时的机械试错，并提升质控结论与 HTML 报告的业务可读性。

## 设计原则

1. 模式 1 与模式 2 使用不同的“结构完整”口径：模式 1 检查正式交付格式，模式 2 检查外部标准是否足以执行质控。
2. 一处根因只计一个问题；一个问题可以影响多个检查能力。
3. 业务语义由模型判断，哈希、重复字段和格式归一化由 Python 完成。
4. 规范对象保留开发枚举，HTML 与文本统一展示中文业务标签。
5. 渲染器继续严格拒绝不合法正式对象，但报错必须告诉调用者如何修正。

## 一、模式 2 标准兼容检查

`validate_certification.py` 保持模式 1 的五位规则编码、正式字段和编码生成规则。

`inspect_standard.py` 增加 `qc` 检查口径。默认口径保持现有正式契约，模式 2 明确使用 `qc`：

- 规则编码必须为非空字符串、全文唯一。
- 同一标准中的规则编码方案必须一致；四位数字、五位数字或统一的字母数字编码均可。
- 逻辑树中的规则引用必须全部存在、不得重复引用。
- 规则必须包含可解释的规则正文。
- 提取项必须能归属于规则；提取项编码缺失只作为兼容性提示，不阻断语义复核。
- 模式 1 专属来源字段或扩展字段差异只记录为兼容性提示。
- 只有重复编码、编码方案混用、悬空引用、缺失规则正文、不可解析逻辑等影响执行的缺陷才分类为 `structured_incomplete`。

四位规则编码本身不得导致条件与结论一致性检查变成 `not_run`。

## 二、问题归因与风险口径

问题增加可选的稳定 `issueId` 和 `relatedCapabilities`：

- `category` 是主归属能力。
- `relatedCapabilities` 表示同一根因影响的其他能力。
- 问题数量按唯一问题计数，相关能力区只链接到同一问题，不复制问题。
- 旧对象不包含新字段时仍可验证和渲染。

输入完整性、材料缺失判断和证据溯源必须分开：

- 用户是否漏传：输入清单确认。
- 审核声称材料缺失但材料实际存在：材料缺失判断错误。
- 审核引用不存在 ID 或把原文挂错材料：证据溯源错误。

风险约束：

- 无问题：`可靠 + 未发现明显风险`。
- 有低/中等级且最终结论不变：通常为 `基本可靠 + 局部判断错误`。
- 只有规则维护问题：根风险为 `仅影响规则质量`。
- 问题可能或已经改变最终结论：结论不得为 `可靠/基本可靠`。
- 影响无法判断：`无法确定 + 暂时无法判断`。

页面不直接显示 `false_approval` 等内部代码，改用完整中文业务表述。

## 三、规范对象准备与渲染诊断

新增确定性的报告准备工具，模型先生成业务草稿，工具再生成正式规范对象：

- 将外部材料正文键归一为 `rawInput.materials[].content`。
- 自动计算 `rawInputSha256`、`inventorySha256` 和 `artifactSha256`。
- 从 `capabilities` 的 `not_run` 项自动生成 `unperformedChecks`。
- 保留用户确认原文与 revision，不推断确认。
- 不对医学事实、问题严重程度或最终结论做静默修正。

正式对象仍保留 11 个根字段。无具体规则归属的问题允许 `ruleCode` 和 `keywordCode` 为空字符串，HTML 显示“不适用”，不得制造虚假编码。

渲染器报错增强：

- `materialEvidence` 类型与证据状态要求一次说清。
- 三处 SHA-256 不一致时返回实际值、期望值和重算提示。
- `capabilities` 与 `unperformedChecks` 原因不一致时展示两侧内容。
- 材料正文键错误时明确提示应使用 `content`。
- category 与 `not_run` 冲突时同时提示两种修正方向。
- 增加 `--explain` 输出稳定的约束摘要。

约束手册、代码和测试必须使用相同字段定义。

## 四、HTML 与文本报告

开发枚举统一映射为中文：

- `completed/partial/not_run` → `已完成/部分完成/未执行`
- `high/medium/low` → `高/中/低`
- 标准类型、审核结果类型、证据状态、复核模式、影响方向和置信度均使用中文。

HTML 页面结构：

1. 质控结论
2. 输入与检查范围
3. 检查能力
4. 影响最终结论的问题
5. 建议/总体建议
6. 五项检查详情
7. 逐规则复核
8. 未执行检查
9. 原始输入

桌面端使用固定左侧目录，移动端使用顶部可横向滚动目录；打印时隐藏目录和“查看”链接。每个检查能力卡片提供“查看”链接，锚定到对应详情。目标区使用 `scroll-margin` 和 `:target` 提示，无需运行时脚本。

能力状态表示“检查是否执行”，不表示“是否发现问题”。卡片同时显示该能力的问题数量和限制原因。

文本报告与 HTML 使用同一中文映射和相同区块顺序。

## 五、测试与兼容性

新增合法基线：

- 外部四位编码、`structured_complete + detailed`。
- 真正结构缺陷、`structured_incomplete + detailed`。

新增单变异非法夹具：

- materialEvidence 类型错误、空/非空错误。
- 三处 SHA 不匹配。
- reason 不一致。
- 正文键错误。
- category 与能力状态冲突。
- 非白名单确认句。
- 多余根字段。

新增标准兼容测试：

- 四位、五位和统一字母数字编码通过。
- 重复、混用和悬空引用失败。
- 模式 1 正式五位编码契约保持不变。

验收要求：

- 现有测试继续通过。
- 新增路径均有 RED-GREEN 回归证据。
- 生成 HTML 离线可用、无外部资源、键盘可访问、移动端和打印布局可用。
- Skill 内容扫描通过。
