# 智能审核质控量规

本量规只复核已确认提供的患者材料、认定标准和审核输出。不得根据病种知识、药物用途、通常治疗方式或概率补全材料空白。先冻结独立的材料事实/证据索引和（若可用）规则判断，再阅读和比较原审核结果；原审核结论不能倒灌到独立索引。

优先在隔离上下文中只提供确认材料和标准，先保存独立复核 JSON 并记录 SHA-256，才读取原审核输出；该模式可称“盲审”。若原审核输出已暴露给同一上下文或隔离不可用，只能称“独立二次复核（非盲）”，必须披露确认偏差限制，仍须在比较前冻结并哈希产物。

## 证据状态、引用与严重度

- 每个问题和逐规则复核都记录 `SUPPORTED`、`CONTRADICTED`、`NOT_FOUND`、`INSUFFICIENT`、`CONFLICTED` 或 `NOT_APPLICABLE`。`SUPPORTED`、`CONTRADICTED`、`INSUFFICIENT`、`CONFLICTED` 至少附一条材料证据；`NOT_FOUND`、`NOT_APPLICABLE` 不附材料证据。
- 每个证据必须可追溯到材料 ID、名称、页/段、原文及位置；没有精确坐标时使用约定的空位置，不得编造坐标或改写原文。
- 规则复核只可为“满足”“不满足”“无法判断”“不适用”。`changed` 与 `potentially_changed` 必须为 `high`；`high` 表示可能改变最终结果，`medium` 影响规则/可执行性/解释，`low` 不直接影响最终结果。
- 错误放行与错误拒绝风险必须分别判断。问题影响代码严格为 `changed`、`potentially_changed`、`unchanged`、`unknown`；问题风险代码严格为 `false_approval`、`false_rejection`、`both`、`none`。交付时分别渲染为“可能导致不符合条件的申请被通过”“可能导致符合条件的申请被拒绝”“两个方向均可能受影响”“未影响最终结论”，不直接向业务用户展示内部代码。
- 当任一问题改变或可能改变结论时，不得给出“可靠”或“基本可靠”；全为错误放行/错误拒绝方向时根风险必须相应一致，`both` 或混合方向时根风险为“暂时无法判断”。存在中/高等级问题时，根风险不得写“未发现明显风险”；最终结论不变但存在证据或判断问题时使用“局部判断错误”。
- 改变或可能改变结论的问题不得标为 `none`，只能标为 `false_approval`、`false_rejection` 或 `both`；`none` 只用于不改变结论的问题。

## 五个质控维度

每个维度无论完成、部分完成还是 `not_run`，都要在能力记录中说明原因，并在适用时逐项输出问题。问题类别必须与同名能力严格对应；标为 `not_run` 的维度不得输出该类别问题。

### 1. 材料缺失判断准确性

审核称材料或证据缺失时，反向检索全部已确认材料，而不只看审核引用的文件。明确区分：整份材料缺失（审核需要的文档根本未提供）、相关证据 `NOT_FOUND`（已提供材料中没有该事实）、`INSUFFICIENT`（有相关内容但不足以支持断言）、`CONTRADICTED`（材料直接相反）和 `CONFLICTED`（材料相互冲突）。不得把“未提及”写成“不存在”。

审核引用清单中不存在的材料 ID，不等于审核声称“患者缺少材料”。若该引用原文能在另一份已提供材料中定位，应归为证据溯源错误；若用户尚未确认完整，先回到输入清单确认，不能提前断定是漏传或幻觉引用。

### 2. 证据提取准确性

核对引文是否存在、含义是否相符、患者是否相符、日期/时间窗是否相符、来源是否相符，以及提取的数值、单位和上下文。不得把否定升级为肯定，把疑似升级为确诊，把既往史升级为当前事实，把排除项升级为支持，把一次治疗升级为持续治疗，或把上位概念升级为更具体的条件。

证据溯源还要检查 `materialId`、材料名称与实际原文是否属于同一材料。原文存在但挂到不存在或错误的材料 ID 时，是一条证据溯源错误；它可以关联材料引用完整性，但不得拆成两条问题重复计数。

### 3. 过度推理

标记从材料未直接表达的诊断、条件、时长、阈值、因果关系或资格结论；没有材料明确表达的事实只能是 `NOT_FOUND`、`INSUFFICIENT` 或“无法判断”，不能由常识补全。

### 4. 条件与结论一致性

在标准可用时，按独立索引逐规则复核，运行逻辑树并比较规则条件、提取值、路径结果和最终结论。标准缺失时，可检查原审核内部矛盾，但不得断言独立政策资格正确与否。仅有简要结果/结论-only 时，证据提取和规则条件检查为 `not_run`，不得猜测审核明细。

### 5. 规则维护质量

完整结构化标准检查结构、可执行性、可追溯性、语义和来源一致性；不完整结构化标准记录精确结构缺陷并只检查有效部分。规则维护质量按下列三类逐项检查：

- **结构**：缺少提取项/提取指南、规则编码、枚举或来源字段；逻辑引用缺失、无效或重复；重复编码。
- **语义**：提取指南非原子；缺少肯定证据、反向证据或无法判断边界；规则与提取项不一致；提取指南重复、矛盾或歧义。
- **完整性**：来源要求的事实没有提取指南；添加来源外条件；AND/OR 或嵌套错误；遗漏认定路径；将辅助细则升级为资格/认定规则。

自然语言临时模型亦检查原文到解释的来源边界和 AND/OR/路径保留，但不得被正式化。存在多种解释但不改变结论时，作为正常问题或说明记录；若解释会改变最终结果，必须使用 `inputScope.interpretationPaths` 记录唯一 `pathId`、解释、`ruleResults`、`finalResult`，且 `qcConclusion` 为“无法确定”，建议人工确认。

## 问题记录与结论

每条问题必须回答四项事实：模型主张是什么、实际材料或标准是什么、为何构成问题、可能影响和建议是什么；同时记录严重度、影响代码、风险代码、置信度、evidenceStatus 和原文位置。一处根因只记录一条问题并只计数一次：`category` 表示主归属能力，`relatedCapabilities` 表示同一问题影响的其他能力，`issueId` 用于跨区块跳转。没有问题也要输出空状态；不能执行的维度不隐藏，使用 `not_run` 和具体原因。

质控结论仅为“可靠”“基本可靠”“存在重大疑点”“不可靠”“无法确定”。根级风险方向仅为“错误放行风险”“错误拒绝风险”“局部判断错误”“仅影响规则质量”“暂时无法判断”“未发现明显风险”。
