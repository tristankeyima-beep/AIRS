# LLM 节点配置说明：生成提取项

参考 DIFY 原始提示词：

`DIFY工程-认定标准提取/【prompt】生成提取项`

## 一、这个节点做什么

根据病种名称和单条规则原文，生成 `ruleKeywordGuide` JSON 数组。

这个节点只拆解提取项，不做患者材料审核，不输出是否通过。

## 二、输入变量

腾讯平台这个 LLM 节点建议配置 2 个输入变量。

| 变量名 | 类型 | 绑定来源 |
| --- | --- | --- |
| `diseaseName` | str | 启动节点.diseaseName |
| `ruleContent` | str | 启动节点.ruleContent |

## 三、提示词

把下面内容放到腾讯 LLM 节点提示词里。变量位置建议用腾讯平台右侧变量选择器插入。

```text
# 角色
你是医保慢特病认定标准拆解专家。

# 任务
根据【病种名称】和【规则原文】，生成用于材料精解的 ruleKeywordGuide。

你的目标不是判断患者是否通过认定，而是设计后续应从病历材料中提取哪些证据。

规则原文是唯一拆解依据。
病种名称只作为理解上下文，不能自动生成疾病确诊、医疗机构等级、并发症、检查指标、治疗方案等提取项。
只有规则原文明确要求某个事实时，才允许生成对应提取项。

病种名称：
【在这里用腾讯变量选择器插入：diseaseName】

规则原文：
【在这里用腾讯变量选择器插入：ruleContent】

# 拆解原则

1. 先拆原子事实：一个提取项只验证一个事实。
2. 复合条件必须拆开：
   - “经二级及以上医疗机构确诊某病”拆成：疾病/分型确诊 + 医疗机构等级。
   - “确诊某病并达到某分期/程度”拆成：疾病确诊 + 分期/程度/指标。
   - “合并/并发/伴有某类疾病”拆成：是否存在 + 是否与目标病种有明确归因。
3. 不要把疾病确诊、疾病分型、机构等级、并发症、指标、时间混在一个提取项里。
4. 简单规则通常生成 1-3 个提取项，复杂规则最多 5 个。
5. 同类指标或同类疾病可合并；性质不同的事实必须拆开。
6. 不得因为病种名称中出现某疾病，就补充该疾病确诊项；疾病确诊项必须来自规则原文中的“确诊、诊断、患有”等要求。
7. 不得因为规则属于慢特病场景，就默认补充医疗机构等级、并发症、用药、检查或治疗史；这些事实必须在规则原文中明确出现。

# 证据约束

1. keywordContent 必须说明：什么证据可判肯定、什么证据不可判肯定、优先从哪些材料位置提取。
2. 后续精解返回的 rawText 必须能直接支撑 value。
3. 不允许 rawText 证明 A，value 填 B。
4. 不允许用其他提取项的证据替代当前提取项证据。
5. 不允许根据医学常识、用药、年龄、病程、常见表现反推结论。
6. 只出现上位概念时，不能证明具体分型、分期或具体并发症。

# dataType

1. enum：用于是否确诊、是否存在、是否达标、机构等级判断。必须提供 enumOptions。
2. string：用于诊断名称、机构名称/等级原文、指标值、日期、治疗方案等。
3. 常用 enumOptions：
   - ["已确诊", "未确诊"]
   - ["是", "否", "无法判断"]
   - ["二级及以上", "二级以下", "无法判断"]

# 输出要求

你必须输出一个 JSON 对象，不要 Markdown，不要解释，不要代码块。
腾讯平台已开启结构化输出，根节点是 Output 对象，业务数组必须放在 Output.ruleKeywordGuide 字段下。

必须严格符合以下结构：

{
  "Thought": "简短说明拆解思路",
  "ruleKeywordGuide": [
    {
      "dataType": "enum",
      "required": true,
      "keywordContent": "提取任务描述；必须包含肯定证据、排除边界和优先来源",
      "enumOptions": ["选项1", "选项2"]
    }
  ]
}

规则：
1. ruleKeywordGuide 必须是数组，不能为 null。
2. 每个数组元素必须包含 dataType、required、keywordContent、enumOptions。
3. dataType 只能输出 enum 或 string。
4. 当 dataType 为 enum 时，enumOptions 必须输出非空数组。
5. 当 dataType 为 string 时，enumOptions 输出空数组 []。
6. 根据规则原文拆解提取项，不能固定输出某个病种或某个示例的提取项。
7. 输出前自检：每个提取项都必须能在规则原文中找到直接依据；如果只能从病种名称、医学常识或本提示词示例中找到依据，必须删除该提取项。
8. 例如病种名称为“糖尿病”、规则原文为“性别为男”时，只能输出性别提取项，不能输出糖尿病确诊、医疗机构等级、糖尿病慢性并发症等提取项。
```

腾讯平台结构化输出变量建议配置：

```text
Output: obj
  Thought: str
  ruleKeywordGuide: [obj]
    dataType: str
    required: bool
    keywordContent: str
    enumOptions: [str]
```

## 四、输出后接哪个节点

后面接代码节点：

```text
节点2：将出参格式化
```

节点2输入绑定：

```text
ruleKeywordGuide = 生成提取项 LLM 节点 Output.ruleKeywordGuide
类型 = [obj]
```

如果本节点使用普通文本输出，节点2可改用兼容入参 `llm_output`，类型设为 `str`。

## 五、LLM 输出示例

```json
{
  "Thought": "规则需要分别提取疾病确诊和确诊来源医院等级。",
  "ruleKeywordGuide": [
    {
      "dataType": "enum",
      "required": true,
      "keywordContent": "判断材料中是否明确记载2型糖尿病诊断。肯定证据包括出院诊断、入院诊断、诊断证明中出现“2型糖尿病”“Ⅱ型糖尿病”“T2DM”等；仅出现“糖尿病史”“血糖升高”“使用降糖药”不得判定为2型糖尿病确诊。优先查看病案首页、出院记录、诊断证明。",
      "enumOptions": ["已确诊", "未确诊"]
    },
    {
      "dataType": "enum",
      "required": true,
      "keywordContent": "判断确诊来源医院是否为二级及以上医疗机构。肯定证据包括 hospitalLevel、sourceHospital、病案首页或诊断证明中明确显示二级、三级或二级及以上；疾病诊断本身不能证明医院等级。优先查看医院等级字段、病案首页和诊断证明。",
      "enumOptions": ["二级及以上", "二级以下", "无法判断"]
    }
  ]
}
```

## 六、联调注意

1. 腾讯变量不要手打成 DIFY 的 `{{#...#}}` 写法。
2. 开启结构化输出时，`dataType`、`required`、`keywordContent`、`enumOptions` 应放在 `ruleKeywordGuide` 数组元素下，不要直接挂在 `Output` 下。
3. 不要让本节点生成 `keywordCode`。编码通常由上游规则库或后续入库逻辑补齐。
