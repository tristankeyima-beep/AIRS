# 代码节点出入参说明：将出参格式化

对应代码：`代码节点.py`

## 这个节点做什么

把“生成提取项”LLM 节点输出的文本解析成腾讯平台后续节点可直接使用的数组。

兼容以下 LLM 输出形态：

```text
腾讯结构化输出对象：{"Thought": "...", "ruleKeywordGuide": [{"dataType": "..."}]}
腾讯结构化输出数组：[{"dataType": "..."}]
JSON 数组
Markdown 代码块里的 JSON 数组
{"ruleKeywordGuide": [...]}
{"result": [...]}
单个 JSON 对象
```

## 入参

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ruleKeywordGuide` | [obj] | 是 | 来自节点1 LLM 的 `Output.ruleKeywordGuide` 数组。 |

## 出参

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `result` | [obj] | 解析后的 `ruleKeywordGuide` 数组。解析失败时返回空数组。 |

## 腾讯平台配置

代码节点输入变量：

```text
ruleKeywordGuide = 节点1.Output.ruleKeywordGuide
类型 = [obj]
```

如果节点1没有开启结构化输出，仍可把兼容入参 `llm_output` 绑定为输出文本，类型设为 `str`。
如果需要调试整段结构化输出，也可临时绑定 `节点1.Output`，类型设为 `obj`。

代码节点输出变量：

```text
result: [obj]
```

结束节点建议绑定：

```text
ruleKeywordGuide = 节点2.result
类型 = [obj]
```

## 可直接粘贴测试的入参示例

```json
{
  "ruleKeywordGuide": [
    {
      "dataType": "enum",
      "required": true,
      "keywordContent": "判断材料中是否明确记载2型糖尿病诊断。",
      "enumOptions": ["已确诊", "未确诊"]
    }
  ]
}
```

## 对应出参示例

```json
{
  "result": [
    {
      "dataType": "enum",
      "required": true,
      "keywordContent": "判断材料中是否明确记载2型糖尿病诊断。",
      "enumOptions": ["已确诊", "未确诊"]
    }
  ]
}
```

## 联调注意

1. 如果 `result` 为空，先检查 `ruleKeywordGuide` 是否实际传到了代码节点。
2. 如果节点1开启结构化输出，腾讯平台字段类型建议把 `ruleKeywordGuide` 设为 `[obj]`，绑定 `节点1.Output.ruleKeywordGuide`。
3. 如果节点1使用普通文本输出，腾讯平台字段类型建议使用兼容入参 `llm_output`，类型设为 `str`。
4. 开启结构化输出时，建议大模型节点输出结构为 `Output.ruleKeywordGuide: [obj]`，不要把 `dataType`、`required`、`keywordContent`、`enumOptions` 直接放在 `Output` 下。
5. 本节点不改写字段含义，只做 JSON 解析和外层拆包。
